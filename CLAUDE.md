# llmtobinary — notes for Claude

- **Debugging a user's generation session:** when the user pastes `llmtobinary debug <production|staging> <session-id>`, run `node scripts/debug-session.mjs <that line>`.
  - It fetches the private R2 archive (server side, plus the browser side if they pressed "Share for debugging") with wrangler.
  - It prints a timeline and saves JSON (and the framebuffer PNG) to `debug-sessions/<env>/<id>/`, which is gitignored.
  - Read `server.json` (`candidates` holds every draft in full; `conversation` is what the model saw) and `browser.json` (full test reports, machine state).
- Deploy: `cd apps/web && pnpm run deploy:staging` / `pnpm run deploy`. Production is **https://llmtobinary.com** (Worker custom domains for the apex and www; `CANONICAL_HOST` 301s page loads from www and workers.dev to it). `routes` is inherited by named envs, so every env sets `"routes": []`; `workers_dev: true` must stay explicit or a deploy with routes disables workers.dev. Pages only reach the Worker for `/` (redirect) via `run_worker_first`, which needs the `ASSETS` binding. E2E: `node tests/e2e/{browser,chip,custom-prompt}-e2e.mjs <url>`.
- The box is shared and often loaded: run builds and tests with `nice`. The workerd suite (`pnpm test:worker`) can time out at pool startup under load.
- **Public program list:** every generation is public, written to `gallery/<id>.json` in the debug R2 bucket by the session DO (`apps/web/worker/gallery.ts`). Rebuild from archives: `POST /api/admin/gallery/rebuild` with `Bearer <GALLERY_ADMIN_KEY>` (key file `~/.config/llmtobinary/gallery-admin-key`, never print it). Take an entry down: `DELETE /api/admin/gallery/<id>` with the same bearer (writes a `gallery-hidden/<sessionId>` marker so it stays down). E2E runs (`--live`) do publish their test prompts.
